# 002 The name stays Husk

Date: 2026-10-17. Status: accepted (the user).

## Context

Husk was named alongside Pare: paring and husking both take the outside off. Before anything was
pushed or published, the user asked for a better-fitting, available name, 4 letters preferred.
Availability checked the same day against nuget.org (`/v3-flatcontainer/<id>/index.json`) and
registry.npmjs.org.

## Options

| Name | NuGet bare / `Extrode.*` | npm | Against it |
|---|---|---|---|
| **Husk** | free / free | `husk` 0.5.3, an unrelated stream library | `husky` (git hooks) on npm; "empty shell" connotation |
| Peel | free / free | 0.0.0 placeholder from 2013 (owner `poying`) | Near-synonym of Pare, same letter and length: `Extrode.Pare.*` and `Extrode.Peel.*` get mixed up; describes Pare's job, not compiling |
| Rind | free / free | 0.0.0 placeholder from 2014 | Weaker tie to the product |
| Pith | free / free | 0.0.0 placeholder from 2013 | Weaker tie to the product |
| Zest, Lithe | taken / free | in use | Bare NuGet ID taken |
| kern, deft, wisp, slim, brix, hull, trim, lean | taken on NuGet or in real use on npm | | |

npm does not hand over squatted names on request: "npm does not resolve squatting claims on
demand" (docs.npmjs.com/policies/disputes); only trademark claims are acted on. So no empty
placeholder name is obtainable on npm.

## Decision

Keep Husk. It pairs with Pare without being confused for it, NuGet is clear, and npm is not a
channel Husk ships on.

## Consequences

- Package IDs: `Extrode.Husk.*` on NuGet.
- If Husk ever gets a JavaScript-facing piece (a Vite plugin, a CLI wrapper), publish it scoped,
  `@extrode/husk`; the npm org `extrode` is unchecked (npmjs.com refused a scripted lookup).
